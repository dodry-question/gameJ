# Движок: какой выбран и почему

> Задача от Ореха: «выбрать движок, тоже написать какой». Здесь — разбор
> простыми словами + готовый текст для отчёта.

---

## Что вообще такое «движок»

**Игровой движок** — программа (или набор библиотек), которая берёт на себя
«скучное и тяжёлое»: рисование картинок на экране, звук, ввод с клавиатуры и
мыши, физику, столкновения, окно/экран, сборку игры в один файл.

Примеры: Unity, Godot, Unreal Engine, GameMaker. Без движка пришлось бы писать
рендер и звук руками — как мы это и делаем для canvas-игры.

---

## Варианты, которые обычно рассматривают

| Движок | Что делает | Плюсы | Минусы |
|---|---|---|---|
| **Godot** | Полноценный движок с редактором, свои скрипты GDScript (похож на Python) | Бесплатный, лёгкий, отличный для 2D, быстрый старт | Нужно учить редактор и свой язык |
| **Unity** | Классический движок для инди и мобильных игр, язык C# | Тонны туториалов, ассет-стор | Тяжёлый, C# для новичка непрост |
| **Unreal Engine** | AAA-движок, Blueprints + C++ | Графика «как в кино» | Огромный, для маленького джема переизбыточен |
| **GameMaker** | 2D-движок со своим языком | Быстро делать аркады | Узкий язык, платная версия для коммерции |
| **GDevelop / Construct** | Без кода: поведения и события визуально | Ноль программирования | Быстро упираешься в гибкость |
| **Web (Vite + TypeScript)** | Нет «движка-редактора»: браузер сам рисует (canvas/WebGL), а код пишем сами | Веб-игра открывается по ссылке, ничего не надо ставить зрителям, идеально под джемы вроде js13kgames, моментальная итерация, hot-reload | Всё вручную: физику, UI и звук пишем сами |

---

## Наш выбор: **Web (браузер) — Vite + TypeScript + Phaser 3**

Почему именно так (и почему это нормальный ответ для геймджема):

1. **Результат — ссылка.** Игрок жмёт ссылку и играет. Не надо скачивать билд,
   ставить рантаймы, бороться с антивирусами — для судей это огромный плюс.
2. **Скорость итерации.** Сохранил файл → страница обновилась (HMR). Для джема,
   где 72 часа, это заметно экономит время.
3. **Меню/настройки уже готовы** в этом репозитории и не привязаны к игре —
   игра подключается через слот сцен (`src/game/scenes/`).
4. **Никакой установки у новичка.** Vite уже стоит (`npm install`), дальше только
   `npm run dev`.
5. **Подходит под профиль джемов.** Браузерные джемы принимают только веб; на
   остальных веб-игры тоже принимают. Наш джем (Siberian Game Jam) — онлайн и
   веб-игры там в почете.
6. **Phaser 3 закрывает «скучное»**: спрайты, физика (arcade), таймеры, ввод,
   камера, аудио — вместо ручного canvas-кода. При этом Phaser — это просто
   JS-библиотека: она живёт внутри нашего веб-проекта и не мешает меню на DOM.

**Минусы, о которых честно сказано:** Phaser тянет ~330 КБ в gzip (для джема
некритично, но js13kgames он не влезет); свой нетворкодный цикл пишем сами
(как и раньше); нет визуального редактора.

### Технический стек (для отчёта)

| Слой | Что это | Зачем |
|---|---|---|
| **Браузер** | Рантайм: `<canvas>`, DOM, WebAudio, localStorage | Сам «движок», который рисует и играет |
| **Phaser 3** | 2D-фреймворк для игр (сцены, физика arcade, спрайты) | Игровая логика и физика без боли; сцены подключаются реестром |
| **Vite** | Сборщик/дев-сервер | Запуск `npm run dev`, сборка `npm run build` в один мини-билд |
| **TypeScript** | JavaScript с типами | Меньше глупых ошибок (опечатка в имени переменной ругнётся сразу) |
| **Vanilla (без React/Vue)** | Обычный JS/DOM для меню | Меньше зависимостей → быстрее собрать на джеме |

## Готовый текст для отчёта ментору

```
Движок: Web (браузер) + Phaser 3. Игровая часть — Phaser (сцены, arcade-физика),
меню и настройки — чистый TypeScript/DOM, сборка через Vite (vanilla-шаблон).

Что это значит на практике:
— игра запускается по ссылке, ничего не надо устанавливать;
— dev-режим: npm run dev, сборка: npm run build;
— меню и настройки отдельно от игры (src/ui, src/settings), визуальный стиль —
  один файл src/theme/themes.css (4 скина, переключение на лету);
— сцены игры подключаются реестром src/game/scenes/, текущая заглушка —
  «бегунок» на Phaser (PlayScene).

Альтернативы рассматривали: Godot (если захотим 2D-проект с редактором),
Unity (если проект затянется и нужна 3D-сцена) — на будущее.
```

---

## Если вдруг захочешь перейти на Godot

Это нормальный сценарий на будущее, но учти: меню/настройки из этого репозитория
на Godot не переедут (это HTML/CSS/TS). Переезжать имеет смысл **до** начала
джема, а не в середине. Порядок такой: поставить Godot → пройти официальный
2D-туториал → перенести идею.
