# AGENTS.md

Перед любой работой прочитай `CONTEXT.md` целиком. Ниже — самое критичное.

## 0. Ветка одна — master

В проекте всегда работаем в единственной главной ветке `master`.

- Не создавать `work/*`, `feature/*`, `fix/*` и любые другие ветки под задачи.
- Не создавать отдельные worktree: рабочая копия одна.
- Все коммиты идут прямо в `master`, без merge и rebase между ветками.
- Если лишняя ветка всё-таки появилась: проверить, что она полностью влита
  (`git branch --merged master`), и удалить её. Незалитые изменения сначала
  перенести в `master`.

## 1. ТЗ получено — работаем по частям

Концепт: оператор за монитором в тёмной комнате, комплекс виден через камеры,
героиней управляем только мышью. Интерфейс — рабочий стол Windows 2000.
Стиль — грязный лоу-поли PS1. Подробности и план — `CONTEXT.md`, раздел 0.

- Работаем **частями**: одна часть = рабочий прототип + скриншот + коммит.
- Не добавлять механики из следующих частей «на всякий случай».
- Части 1–2 (рабочий стол в 3D, терминал TDS с картой и камерой, героиня)
  готовы; следующая — головоломка.
- Камеры и карта живут только в TDS (`tds.exe`): карта блока C, удержание
  узла две секунды → подключение → постепенная загрузка кадра. В Netscape
  камер нет и быть не должно. TDS ставится из письма: скачивание вложения
  показывает вирус-тыкву и кладёт ярлык `tds.exe` на рабочий стол. Браузер
  остаётся для справки и интернета.
- Готовые меню, скины и UI-фреймворки по-прежнему нельзя: интерфейс рисуется
  с нуля в canvas.

## 2. FNAF запрещён

Никаких ночных смен с камерами, аниматроников, монстров в кадре, скримеров
и хоррора на камерах. Камеры — инструмент механики, а не источник страха.

Новое ТЗ содержит похищение и маньяка. До реализации этих сцен — согласовать
с пользователем (см. `CONTEXT.md`, раздел 9). Даже после согласования: без
скримеров, без монстра в кадре и без покадрового насилия.

## 3. Стек

Vite + TypeScript + three. Без Phaser, Unity, Godot, React/R3F.
UI и стили пишутся с нуля — готовых меню и кнопок в проекте нет намеренно.

## 4. Коммить и пушить постоянно

Цель — **свежесть проекта для всех разработчиков**. Любой человек или ИИ в любой
момент должен видеть актуальный код в `origin/master`, а не чужую недоделанную
рабочую копию.

- Коммит после каждого логического шага: файл готов, фича работает, баг закрыт,
  док обновлён. Не копить изменения до «финала».
- Сразу после коммита — `git push origin master`. Не оставлять коммиты локально.
- Перед пушем: `npm run typecheck` (и `npm run build`, если менялась сборка).
  Битое состояние в общую ветку не пушим.
- Сообщения коммитов осмысленные, по-русски, в императиве: `добавь сетку фидов`,
  `почини ресайз вьюпорта`, `обнови CONTEXT.md`.
- Не `--force`, не переписывать чужую историю, не коммитить `node_modules`,
  `dist`, `.env` и секреты.
- Начало работы — `git pull --rebase`, чтобы не разъезжаться с остальными.
